## Хэсэг A: Category-Partition (гараар) — POST /transfer

### Давуу эрэмбэ

Нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал `from` (NO_FROM → FROZEN) → `to` (NO_TO → SAME_ACCOUNT) → `amount` (BAD_AMOUNT) → INSUFFICIENT → LIMIT дарааллаар эхний таарсан алдааг буцаана гэж үзнэ, учир нь эхлээд данснуудын хүчинтэй эсэхийг, дараа нь дүнгийн утгыг, хамгийн сүүлд дансны төлөвийг (үлдэгдэл, лимит) шалгах нь өгөгдлийн хамаарлын дагуу логик дараалал юм.

### A1 — Сонголт ба төлөөлөх утгууд

Далд орчны сонголт: `balance` (`from` дансны үлдэгдэл), `limit_left` (өдрийн лимитийн үлдэгдэл). Валют өөр үед хоёуланг нь `amount × ханш`-тай харьцуулна.

| Параметр | Сонголт | Төлөөлөх утга |
|---|---|---|
| from | хүчинтэй | байгаа, царцаагдаагүй данс |
| | царцаагдсан | байгаа, frozen данс |
| | байхгүй | системд байхгүй ID |
| to | хүчинтэй | байгаа, from-оос өөр данс |
| | байхгүй | системд байхгүй ID |
| | from-той ижил | to = from |
| amount | ердийн эерэг | 100 |
| | хамгийн бага эерэг | 0.01 |
| | тэг | 0 |
| | сөрөг | -1 |
| currency | дансныхтай ижил | from-ийн валют |
| | өөр валют | ханшийн хөрвүүлэлттэй |
| balance (далд) | хүрэлцээтэй | үлдэгдэл > amount |
| | яг тэнцүү | үлдэгдэл = amount |
| | хүрэлцэхгүй | үлдэгдэл < amount |
| limit_left (далд) | хүрэлцээтэй | лимитийн үлдэгдэл > amount |
| | яг тэнцүү | лимитийн үлдэгдэл = amount |
| | хэтэрсэн | лимитийн үлдэгдэл < amount |

### A2 — Хязгаарлалтууд

| Сонголт | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| from = байхгүй | [ERROR] | `ERROR_NO_FROM` буцна, бусад параметрийг шалгахгүй тул нэг удаа тестлэхэд хангалттай. |
| from = царцаагдсан | [ERROR] | `ERROR_FROZEN` буцна, дараагийн шалгалтуудыг далдалдаг. |
| to = байхгүй | [ERROR] | `ERROR_NO_TO` буцна. |
| to = from-той ижил | [ERROR] | `ERROR_SAME_ACCOUNT` буцна. |
| amount = 0 | [ERROR] | `ERROR_BAD_AMOUNT` (amount ≤ 0), үлдэгдэл харьцуулах утгагүй. |
| amount = сөрөг | [ERROR] | `ERROR_BAD_AMOUNT`, хязгаарын нөгөө тал тул тусад нь тестлэнэ. |
| amount = 0.01 | [SINGLE] | Хамгийн бага хязгаарын утга, алдаа биш; нэг тест хангалттай. |
| balance = хүрэлцэхгүй | [IF valid_inputs] | Зөвхөн from, to, amount бүгд хүчинтэй үед `ERROR_INSUFFICIENT` утгатай. |
| limit_left = хэтэрсэн | [IF valid_inputs] | Зөвхөн оролт хүчинтэй үед `ERROR_LIMIT` утгатай. |

`valid_inputs` = from хүчинтэй ∧ to хүчинтэй ∧ amount > 0.

balance, limit_left-ийн алдааны сонголтыг [ERROR] биш [IF] болгосон нь INSUFFICIENT ба LIMIT зэрэг гарах давхар нөхцөлийг тестлэхийн тулд юм.

**Тооны тооцоо.**

- Бүрэн олонлог: 3 (from) × 3 (to) × 4 (amount) × 2 (currency) × 3 (balance) × 3 (limit_left) = 648
- Нэг удаа тестлэх: from 2 + to 2 + amount 2 (0, сөрөг) + amount 0.01 (SINGLE) 1 = 7
- Үндсэн хослол: 1 × 1 × 1 (amount = 100) × 2 × 3 × 3 = 18
- Нийт: 7 + 18 = 25

**648 → 25**

## Хэсэг B: PICT — pairwise covering array

PICT-ийг `~/tools/pict`-д эх кодоос бүтээсэн (хувилбар: `results/pict-build.txt`). Бүх ажиллуулалт анхдагч (`/r`-гүй) тул үр дүн давтагдана.

### B1 — Лекцийн браузерын жишээ

| Хүрээ | Мөрийн тоо | Файл |
|---|---|---|
| 2-way (pairwise) | 10 | `results/browser-2way.txt` |
| 3-way (`/o:3`) | 20 | `results/browser-3way.txt` |
| Бүрэн олонлог (3·3·2·2·2·2) | 144 | — |

**2-way: 10 мөр гарсан, лекцийн гар шийдэл 9 мөр.** PICT нэг мөр нэмэх бүрт тухайн мөчид хамгийн олон шинэ хос хамарах мөрийг сонгодог greedy алгоритм бөгөөд хамгийн цөөн мөрийг олохыг баталгаажуулдаггүй. Хамгийн бага covering array олох нь тооцооллын хувьд хэцүү бодлого тул PICT хурдан, хангалттай сайн (ойролцоо) шийдэл өгдөг ч оновчтой 9-д үргэлж хүрэхгүй. Хос бүр хамрагдсан гэдэг баталгаа харин хэвээр.

**3-way: 20 мөр, бүрэн олонлогийн 144-ийн ойролцоогоор 14% (86%-иар цөөн).** Гурвалсан хамаарал хүртэл хамруулсан мөртлөө тестийн тоо үлэмж багассан.

### B2 — Шилжүүлгийн модель

Моделийн параметрүүд нь A1-ийн сонголтууд. `balance`, `limit_left` далд сонголтуудыг `Amount`-ын `OverBalance` / `OverLimit` утгад нэгтгэсэн тул PICT-ийн модель дөрвөн параметртэй.

`transfer.model`-ийн хязгаарлалтууд (A2-оос):
- `IF [From] <> "Valid" THEN [Amount] = "Normal";` — from буруу бол дүнгийн алдааг хамт тестлэхгүй (error masking).
- `IF [To] <> "Valid" THEN [Amount] = "Normal";` — to буруу бол мөн адил.
- `IF [From] <> "Valid" THEN [To] = "Valid";` — from-ийн алдаа to-ийн алдаатай хамт орохгүй (A2-ын [ERROR] нэг удаа). Энэ гуравдахь хязгаарлалтыг дээрх хоёрыг нэмж өөрөө оруулсан.

**Гурван хувилбарын харьцуулалт**

| Хувилбар | Мөрийн тоо | Happy path мөр | 0 алдаа | 1 алдаа | 2 алдаа | 3 алдаа |
|---|---|---|---|---|---|---|
| `transfer-nc` (хязгаарлалтгүй) | 13 | 1 | 1 | 1 | 8 | 3 |
| `transfer` (A2-ын хязгаарлалттай) | 14 | **0** | 0 | 14 | 0 | 0 |
| `transfer-neg` (`~` ашигласан) | 16 | 2 | 2 | 14 | 0 | 0 |

(Нэг мөр дэх алдаа = `From`≠Valid, `To`≠Valid, `Amount`≠Normal гэсэн баганын тоо.)

**Гаралтыг уншсан дүгнэлт**
- **Хязгаарлалтгүй:** happy path 1 мөр гарсан боловч 13 мөрийн 11-д нь 2-3 алдаа зэрэг байна (жишээ нь `Missing, Missing, OverBalance, Different`). Эхний алдаа бусдыг нууна, мөн `From = Missing` үед `OverBalance`-ийн үлдэгдэл гэж байхгүй тул мөр утгагүй. Иймэд олон алдаатай мөр юуг шалгаж байгаа нь тодорхойгүй, зөвхөн давуу эрэмбээс хамаарна.
- **Хязгаарлалттай:** нэг мөрөнд яг нэг алдаа, мөр бүр нэг алдааны ангийг шалгана. Гэхдээ **happy path мөр гарсангүй**. Pairwise нь (Valid, Valid, Normal) гурвалыг шаарддаггүй, `Valid–Valid` хос нь `OverBalance` зэрэг алдаатай мөрөөр хамрагдсан тул PICT нэмэлт мөр өгөөгүй. Иймд happy path-ийг гараар нэмэх шаардлагатай.
- **Мөрийн тоо:** хязгаарлалттай (14) нь хязгаарлалтгүйгээс (13) олон болсон. Хязгаарлалт нь утгагүй хослолыг хасах бөгөөд мөрийн тоог багасгах зорилготой биш. Үлдсэн боломжит хосуудыг бүрэн хамрахын тулд PICT нэмэлт мөр өгсөн.
- **`~`-тэй:** мөр бүрт хамгийн ихдээ нэг сөрөг утга орсон (A2-ын [ERROR]-той дүйнэ), happy path 2 мөр (`Same`/`Different` валюттай) гарсан.

**`~` хэрэглэхэд A2-ын хязгаарлалт хэрэгтэй хэвээр үү?** Энэ моделийн хувьд A2-ын [ERROR]-тай холбоотой гурван хязгаарлалт шаардлагагүй болсон, учир нь `~` нь нэг мөрөнд нэг л алдаа оруулдаг. Харин хоёр зүйл хэвээр хэрэгтэй:
1. A2-ын [IF] хязгаарлалт (ж. нь `balance`, `limit_left`-ийг тусад нь параметр болговол "алдаа нь зөвхөн бусад оролт хүчинтэй үед" гэсэн хязгаарлалт).
2. Давхар нөхцөл `~`-тэй моделд огт орохгүй (нэг мөрөнд хоёр сөрөг утга гарахгүй). Тиймээс A3-ийн #14, #16, #17-г гараар нэмж, давуу эрэмбээр oracle-ыг нь тогтооно.
